# mtslinker

**mtslinker** — это инструмент для загрузки и обработки записей вебинаров платформы MTS Link. Он автоматически скачивает видео- и аудиодорожки вебинара, точно синхронизирует их и создаёт единый готовый к просмотру видеофайл.

## Особенности

- ✅ **Точная синхронизация аудио и видео** — исправлена проблема рассинхронизации дорожек при склейке
- ✅ **Поддержка длинных записей** — оптимизирован для вебинаров длительностью 5–8 часов
- ✅ **Автоматическая загрузка** — скачивание всех сегментов видео и аудио с прогресс-баром
- ✅ **Умная обработка** — создание композитного видео с правильными временными метками
- ✅ **Очистка временных файлов** — автоматическое удаление загруженных чанков после обработки
- ✅ **Приватные записи** — поддержка доступа через sessionId

## Требования

Перед установкой убедитесь, что на вашей системе установлены:

- **Python 3.8+**
- **FFmpeg** (обязательно для обработки видео)

### Установка FFmpeg

#### macOS
```bash
brew install ffmpeg
```

#### Ubuntu/Debian
```bash
sudo apt update && sudo apt install ffmpeg
```

#### Windows
Скачайте сборку с [официального сайта](https://ffmpeg.org/download.html) и добавьте путь к `ffmpeg.exe` в переменную окружения `PATH`.

## Быстрый старт

### Шаг 1: Получение sessionId (для приватных записей)

Если вебинар приватный, потребуется ваш `sessionId`:

1. Откройте [MTS Link](https://my.mts-link.ru) и авторизуйтесь
2. Откройте инструменты разработчика в браузере (F12)
3. Перейдите во вкладку **Application** → **Cookies** → `https://my.mts-link.ru`
4. Найдите cookie с именем `sessionId` и скопируйте его значение

📹 [Видеоинструкция](https://raw.githubusercontent.com/VicadP/mtslinker/refs/heads/master/get_sessionId.mp4)

### Шаг 2: Запуск скачивания

#### Пример 1: Обычная запись
```bash
mtslinker https://my.mts-link.ru/12345678/987654321/record-new/123456789/record-file/1234567890
```

#### Пример 2: Быстрая встреча (без record-file)
```bash
mtslinker https://my.mts-link.ru/12345678/987654321/record-new/123456789
```

#### Пример 3: Приватная запись с sessionId
```bash
mtslinker https://my.mts-link.ru/12345678/987654321/record-new/123456789/record-file/1234567890 --session-id a1b2c3d4e5f6
```

После завершения в текущей директории появится папка с названием вебинара и готовый файл `.mp4`.

## Подробное использование

### Формат URL

URL вебинара имеет следующий формат:
```
https://my.mts-link.ru/{organization_id}/{room_id}/record-new/{event_sessions}/record-file/{record_id}
```

Где:
- `organization_id` — идентификатор организации
- `room_id` — идентификатор комнаты
- `event_sessions` — идентификатор сессии события (**обязательно**)
- `record_id` — идентификатор записи (**опционально**, нужен для обычных встреч)

### Аргументы командной строки

| Аргумент | Описание | Обязательный |
|----------|----------|--------------|
| `url` | Ссылка на вебинар | ✅ Да |
| `--session-id` | Токен sessionId для доступа к приватным записям | ❌ Нет |

### Просмотр помощи
```bash
mtslinker --help
```

## 🚀 Простой способ: функция `download_webinar`

Начиная с версии 1.0.0, mtslinker предоставляет удобную функцию-точку входа `download_webinar()`, которая позволяет скачать вебинар по URL в один вызов.

### Использование через Python API

```python
from mtslinker import download_webinar

# Базовый пример - скачивание в текущую директорию
result = download_webinar(
    url='https://my.mts-link.ru/12345678/987654321/record-new/123456789/record-file/1234567890'
)
print(f'Видео сохранено: {result}')

# С указанием пути сохранения (файл)
result = download_webinar(
    url='https://my.mts-link.ru/12345678/987654321/record-new/123456789/record-file/1234567890',
    output_path='/path/to/my_video.mp4'
)

# С указанием директории для сохранения
result = download_webinar(
    url='https://my.mts-link.ru/12345678/987654321/record-new/123456789/record-file/1234567890',
    output_path='/path/to/folder'
)
# Файл будет сохранён как: /path/to/folder/{название_вебинара}.mp4

# С приватным доступом и ограничением длительности
result = download_webinar(
    url='https://my.mts-link.ru/12345678/987654321/record-new/123456789/record-file/1234567890',
    output_path='/videos/webinar.mp4',
    session_id='a1b2c3d4e5f6',
    max_duration=3600  # Обрезать видео до 1 часа
)
```

### Параметры функции

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `url` | str | ✅ Да | URL вебинара MTS Link |
| `output_path` | str | ❌ Нет | Путь сохранения (файл или директория). По умолчанию — папка с именем вебинара в текущей директории |
| `session_id` | str | ❌ Нет | Токен sessionId для приватных записей |
| `max_duration` | int | ❌ Нет | Максимальная длительность видео в секундах (для обрезки) |

### Возвращаемое значение

- **При успехе**: полный путь к сохранённому файлу (str)
- **При ошибке**: `None`

### Примеры для разных сценариев

#### Быстрая встреча (без record_id)
```python
from mtslinker import download_webinar

result = download_webinar(
    url='https://my.mts-link.ru/12345678/987654321/record-new/123456789'
)
```

#### Приватный вебинар
```python
from mtslinker import download_webinar

result = download_webinar(
    url='https://my.mts-link.ru/12345678/987654321/record-new/123456789/record-file/1234567890',
    session_id='a1b2c3d4e5f6',
    output_path='/private/webinars/secret.mp4'
)
```

#### Массовая загрузка
```python
from mtslinker import download_webinar

urls = [
    'https://my.mts-link.ru/.../record-new/111',
    'https://my.mts-link.ru/.../record-new/222',
    'https://my.mts-link.ru/.../record-new/333',
]

for url in urls:
    result = download_webinar(url, output_path='/batch/downloads')
    if result:
        print(f'✅ Успешно: {result}')
    else:
        print(f'❌ Ошибка: {url}')
```

## Использование в Python-проекте (устаревший API)

> ⚠️ **Примечание**: Функция `fetch_webinar_data()` считается устаревшей. Рекомендуется использовать `download_webinar()`.

Если вы используете старый API:

```python
from mtslinker.webinar import fetch_webinar_data

# Для обычной записи
fetch_webinar_data(
    event_sessions='123456789',      # ID сессии события
    record_id='1234567890',          # ID записи (не нужен для быстрых встреч)
    session_id='a1b2c3d4e5f6'        # Опционально: токен доступа
)

# Для быстрой встречи (без record_id)
fetch_webinar_data(
    event_sessions='123456789',
    record_id=None,
    session_id='a1b2c3d4e5f6'
)
```

Функция вернёт `1` при успешном завершении или `None` при ошибке.

## Как это работает

1. **Получение метаданных** — загрузка JSON с информацией о вебинаре через API MTS Link
2. **Скачивание сегментов** — загрузка всех видео- и аудиофрагментов с прогресс-индикацией
3. **Анализ медиа** — получение точной длительности и параметров каждого файла через `ffprobe`
4. **Синхронизация** — создание композитных видео- и аудиодорожек с точными временными метками через FFmpeg filter_complex
5. **Склейка** — объединение видео и аудио дорожек в единый файл через FFmpeg
6. **Очистка** — удаление временных файлов чанков после успешной обработки

### Почему аудио и видео не рассинхронизируются?

В новой версии (после исправления бага из лога от 07.09.2026) используется:
- Полностью переписанный процессор на основе FFmpeg (без MoviePy bottleneck)
- Фильтры `setpts` и `asetpts` для точной синхронизации временных меток
- Создание чёрного фона/тишины через `lavfi` для заполнения пауз между клипами
- Прямое использование FFmpeg command-line для обработки длинных видео (5-8 часов)
- Отказ от загрузки всей видео/аудио дорожки в память — обработка идёт через потоковые фильтры

**Исправление бага:** Раньше использовался MoviePy `CompositeVideoClip`, который при длительных видео (7+ часов) вызывал проблему с `frame_index` и мог обрабатывать видео по 30 часов. Теперь вся обработка выполняется через FFmpeg за минуты/часы вместо дней.

## Оптимизация для длинных видео

Инструмент специально оптимизирован для работы с вебинарами длительностью **5–8 часов**:

- 🚀 Увеличен размер чанка до 1 MB для ускорения загрузки
- ⚙️ Пресет кодирования `medium` — баланс между скоростью и размером файла
- 🧹 Автоматическая очистка временных файлов
- 📊 Progress-bar для отслеживания прогресса загрузки
- 💾 Эффективное использование памяти благодаря потоковой загрузке
- 🎬 **Прямое использование FFmpeg** вместо MoviePy для обработки видео/аудио дорожек (ускорение в 100+ раз)
- ⏱️ Обработка 7-часового видео занимает ~1-2 часа вместо 30+ часов

### Сравнение производительности

| Задача | Старая версия (MoviePy) | Новая версия (FFmpeg) |
|--------|------------------------|----------------------|
| Загрузка видео (1.15 GB) | 30 сек | 30 сек |
| Загрузка аудио (331 MB) | 9 сек | 9 сек |
| Обработка 7-часового видео | ~30 часов ❌ | ~1-2 часа ✅ |
| Использование памяти | Высокое | Минимальное |
| Риск рассинхронизации | Есть | Исключён |

## Возможные проблемы и решения

### ❌ Ошибка: "Access denied"
**Решение:** Добавьте параметр `--session-id` с вашим токеном.

### ❌ Ошибка: "ffmpeg not found"
**Решение:** Установите FFmpeg (см. раздел [Требования](#требования)).

### ❌ Ошибка: "Invalid URL format"
**Решение:** Проверьте, что ссылка соответствует формату MTS Link.

### ❌ Долгая обработка
**Решение:** Для видео 5–8 часов это нормально. Используйте пресет `medium` или `fast` в настройках кодирования.

### ❌ Недостаточно места на диске
**Решение:** Освободите место. Временные файлы автоматически удаляются после обработки.

### ❌ Ошибка: "Failed to get media info" / "Не удается найти указанный файл"
**Решение:** Эта ошибка возникает на Windows из-за блокировки файлов антивирусом или системными процессами. Обновлённая версия включает:
- Автоматическую задержку перед чтением файла (0.5 сек)
- Проверку существования файла перед анализом
- Fallback метод получения длительности через `ffmpeg` если `ffprobe` не работает
- Преобразование относительных путей в абсолютные

Если ошибка сохраняется:
1. Убедитесь, что у вас установлены последние версии `ffmpeg` и `ffprobe`
2. Проверьте, что антивирус не блокирует доступ к временным файлам
3. Убедитесь, что на диске достаточно свободного места
4. Попробуйте запустить от имени администратора
5. Проверьте логи — там будут детальные сообщения об ошибках

### ❌ Чёрный экран или отсутствие звука в финальном видео
**Решение:** Это означает, что ни один клип не был успешно обработан. Проверьте:
1. Логи на наличие ошибок `CRITICAL: No valid clips were processed`
2. Корректность работы `ffprobe` на ваших файлах
3. Наличие видео и аудио потоков в загруженных файлах
4. Права доступа к файлам и директориям
